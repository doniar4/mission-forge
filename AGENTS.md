# Правила для ИИ-агентов и коллабораторов

Mission Forge — образовательная игра: игрок проектирует космическую миссию, запускает её и получает разбор причин успеха или провала. Одиночная игра и командная до 3 человек.

**Полное описание проекта — [docs/HANDOFF.md](docs/HANDOFF.md).** Прочитайте разделы, относящиеся к вашей задаче, прежде чем менять код. Там описаны все модули, функции, формулы, протокол командной игры и список задач с критериями готовности.

## Команды

```bash
npm install
npm run dev     # http://localhost:5173
npm test        # тесты ядра и баланса — обязательно перед коммитом
npm run build   # проверка типов и сборка
```

## Жёсткие правила

1. `src/engine/` — только чистые функции: без React, DOM, сети, `Date.now()` и `Math.random()`. Случайность — только через `rng()` в `simulate.ts`.
2. `simulate(design, scenario, difficulty, seed)` обязан быть детерминированным: на этом держится командная игра (по сети передаётся только seed).
3. Каждая строка для игрока — на русском и английском (тип `L` или `t('рус', 'eng')`).
4. Любой проект, пришедший извне (localStorage, ссылка, сеть), проходит через `sanitize()`.
5. Меняете числа в `catalog.ts`, `scenarios.ts`, `evaluate.ts`, `simulate.ts`, `report.ts` — запустите `npm test` и посмотрите строки баланса. Эталон перестал проходить — баланс сломан.
6. Командная логика меняется только в `engine/team.ts` (`reduce` — чистый судья) и покрывается тестами в `team.test.ts`.
7. Новое замечание комиссии: `evaluate.ts` + таблица `WHERE` в `ui/Studio.tsx`. Новое поле проекта: `types.ts`, `emptyDesign`, `sanitize`, `ROLE_FIELDS`, интерфейс раздела, тесты.
8. Никаких секретных ключей во фронтенде: сайт статический и публичный. ИИ-наставник — только через серверную функцию (HANDOFF, задача 10.4).
9. Никаких логотипов, названий и стиля реальных организаций и компаний; ракеты и сервисы вымышленные.
10. Имена игроков и чат не отправлять во внешние сервисы.
11. Интерфейс должен работать от ширины 375 px без горизонтальной прокрутки, с клавиатуры и с `prefers-reduced-motion`.
12. `three` импортируется только внутри `src/three/`, а экраны подключают сцены через `import()`: 3D-код не должен попадать в основной файл сборки, страница показывается сразу, сцена догружается после. У каждой сцены есть замена без WebGL.
13. 3D-сцены и `flight/director.ts` ничего не решают: исход миссии определяют только `simulate()` и `evaluate()`. Сцена не вызывает `Math.random()` для того, что влияет на числа игрока.
14. Модели создаются скриптами `tools/blender/*.py` и экспортируются в `public/models/`; превью для карточек — `render_thumbs.py` в `public/thumbs/` (рендерить в фоновом Blender `-b`, рендер из открытого Blender через MCP его роняет). Новая деталь в каталоге = её картинка в `render_thumbs.py` и запись в `ui/hangar/parts.ts`. Не добавляйте чужие модели, текстуры и фотографии без явной свободной лицензии и записи об источнике в README.
15. Меняете числа ракет в `engine/ascent.ts` — запустите `npm test` и посмотрите строки выведения: каждая ракета обязана выводить свою паспортную нагрузку на опорную орбиту с небольшим остатком топлива.

## Принципы игры

- У каждого решения есть цена минимум в двух ресурсах.
- У каждой миссии минимум два рабочих решения.
- Объяснять причину с числами игрока и что можно поменять, а не «правильно/неправильно».
- Блокер — только невозможное или неутверждаемое; всё остальное — риск, который проявится в полёте.
- Цели ролей в команде должны конфликтовать.

## Стиль работы

- Код, комментарии и сообщения коммитов — на английском; общение с владельцем проекта — на русском.
- Новая работа — в ветке и через PR; в описании PR — что изменилось, как проверено, строка баланса, если менялись числа.
- Изменили поведение — обновите `docs/HANDOFF.md` в том же PR.
