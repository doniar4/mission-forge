# Mission Forge

Образовательная игра: спроектируйте космическую миссию, запустите её и разберитесь, почему она удалась — или нет.

*An educational game: design a complete space mission, fly it, and learn why it worked — or did not. The interface is available in Russian and English.*

Игрок получает заявку от «заказчика» (найти лесные пожары, составить карту лунного льда, предсказывать марсианскую погоду), выбирает орбиту, научные приборы, источник энергии, связь, двигатель и ракету, а затем наблюдает, как миссия проживает свои годы на орбите. Каждое решение чего-то стоит: прибор добавляет науку, но тянет за собой массу, мощность, данные и деньги. После полёта игра объясняет простым языком, какие решения сработали.

## Что уже есть

- **Пять миссий и песочница**: околоземная орбита, Луна, точка L1 и Марс, три уровня сложности.
- **Конструктор аппарата** из семи разделов: задача, орбита, приборы, энергия, платформа, связь и данные, запуск и план.
- **Шесть ресурсов на виду**: масса, энергия, данные, бюджет, срок разработки и прогноз науки пересчитываются при каждом изменении.
- **Комиссия по готовности**: обязательные замечания не дают запустить миссию, риски — дают, но их последствия проявятся в полёте. Каждое замечание объясняет причину.
- **Симуляция полёта** по месяцам: деградация солнечных батарей, тень и батарея, узкий канал связи, солнечные бури, отказы, сход с орбиты.
- **Разбор миссии**: счёт из семи слагаемых, оценка и текстовый анализ «почему так вышло».
- **Таблица лучших результатов**, сохранение проекта и ссылка, по которой проект открывается у другого человека.
- **Чертёж аппарата**, который меняется вместе с проектом.

Что в планах (сетевая игра на четверых, случайные события на этапе разработки, сравнение проектов) — в [docs/PLAN.md](docs/PLAN.md).

## Запуск

Нужен Node.js 20 или новее.

```bash
npm install
npm run dev
```

Откройте адрес, который покажет Vite (обычно http://localhost:5173).

```bash
npm test        # тесты расчётного ядра
npm run build   # проверка типов и сборка в dist/
```

## Как устроен код

```
src/
  engine/            расчётное ядро без зависимостей от интерфейса
    types.ts         типы: орбита, компонент, проект, результат
    catalog.ts       орбиты, приборы, компоненты, ракеты, уровни сложности
    scenarios.ts     миссии: задача, бюджет, сроки, подходящие орбиты
    evaluate.ts      бюджеты массы, энергии, данных, денег, времени + замечания комиссии
    simulate.ts      полёт по месяцам с детерминированным генератором случайных чисел
    report.ts        счёт и объяснение результата
    engine.test.ts   тесты и проверка баланса на эталонных проектах
  ui/                экраны: главная, конструктор, полёт, разбор
  store.ts           состояние игры (zustand), сохранение в браузере, ссылки на проекты
  i18n.ts            переключение русского и английского
```

Ядро — чистые функции: `evaluate(design, scenario, difficulty)` возвращает все бюджеты и замечания, `simulate(design, scenario, difficulty, seed)` — полную историю полёта. Один и тот же `seed` всегда даёт один и тот же полёт, поэтому в сетевой игре достаточно передать проект и число.

## Насколько это реалистично

Числа упрощены, но пропорции настоящие:

- Топливо считается по формуле Циолковского с учётом массы баков.
- Солнечные батареи дают мощность только на свету и слабеют с расстоянием от Солнца (у Марса — 43%) и с годами.
- Объём переданных данных — это скорость канала, умноженная на время связи со станциями.
- Магнитные катушки ориентации работают только в магнитном поле Земли.
- На солнечно-синхронной орбите аппарат обязан сойти с орбиты после завершения работы.

Сознательное упрощение: падение скорости связи с расстоянием в игре сжато (в реальности оно намного круче и компенсируется огромными наземными антеннами). Названия ракет вымышлены.
